# wuAPI 开发与发布说明

## 标准工作目录

- 当前标准开发目录：`E:\SoftWare\Project\wuAPI-worktree`
- `origin`：`https://github.com/NerdWu/wuAPI`
- `upstream`：`https://github.com/wang1970/API-Switch`
- 历史参考目录：`E:\SoftWare\Project\wuAPI`

不要继续在 `E:\SoftWare\Project\API-Switch` 或旧 `wuAPI` 目录里直接做功能开发。

## 日常开发流程

1. 开始编辑前先执行：

```powershell
git status --short --branch
```

2. 前端用户行为改动优先落在 `src/`，Rust 代理和数据库改动优先落在 `src-tauri/src/`。
3. 修改后至少验证：

```powershell
corepack pnpm typecheck
corepack pnpm build:renderer
corepack pnpm build
```

4. 未经确认，不执行 `git push`。

## 同步上游流程

1. 获取上游更新：

```powershell
git fetch --prune upstream
```

2. 先审计差异，再决定是否迁移。
3. 只迁移会影响 `wuAPI` 实际产品面的内容：
   - 代理行为
   - 协议兼容
   - API 池 / 分组路由
   - 设置与用户工作流

不要把旧目录中的构建产物、日志、数据库文件或过时架构直接拷贝进来。

## 本地发布构建

推荐命令：

```powershell
.\build.ps1
```

等价手动流程：

```powershell
corepack pnpm build:versioned
```

构建结果：

- 运行文件：`src-tauri\target\release\wuAPI.exe`
- 版本化发布副本：`release\wuAPI_<version>_<timestamp>.exe`

`src-tauri\target\release\api-switch.exe` 属于历史残留，不作为当前发布目标。

## 发布前检查

1. `git status` 干净，或只包含明确要发布的跟踪改动。
2. 版本号保持一致：
   - `package.json`
   - `src-tauri/tauri.conf.json`
   - `src-tauri/Cargo.toml`
3. `corepack pnpm typecheck` 通过。
4. `corepack pnpm build` 通过。
5. 确认最终运行文件名是 `wuAPI.exe`。
6. 用当前本地设置和 API 池数据做一次基本冒烟验证。

### 字体规则

- 软件界面字体最高优先级固定为系统已安装字体 `抖音美好体`。
  - 该规则已写入 `AGENTS.md`，后续新增页面、组件、图表和代码样式都必须优先使用该字体。

### 系统设置

- 删除“通用设置”里的语言下拉框。
  - 原因：当前软件按个人中文主线维护，不再需要在设置页暴露中英文切换入口。
  - 保留行为：桌面端仍由应用入口强制使用中文，不改底层 `locale` 字段和 i18n 资源。
- 将“冷却恢复时间”从滑块改为数字输入框。
  - 原因：滑块不利于精确输入，也和上方端口、失败阈值、连接超时等配置项形式不一致。
  - 当前限制：输入值仍限制在 `30 - 1800` 秒，保存逻辑仍通过原 `circuit_recovery_secs` 字段。

### API 管理

- 删除顶部操作区里的“默认分组：xxx”提示。
  - 原因：当前分组已经由下方分组标签表达，额外提示重复且占空间。
- 删除“筛选渠道”下拉框。
  - 原因：当前使用方式以 API 分组为主，不再依赖渠道筛选；保留它会干扰分组管理工作流。
  - 相关代码：移除 `filterChannel` 状态、分页查询中的 `channelId` 参数和 `ChannelFilter` 组件。
- 保留搜索框，但搜索不再和渠道筛选混用。
  - 说明：搜索仍可用于临时定位模型名、显示名或渠道字段，但不再占据渠道筛选控件的位置。
- 移除模型卡片右上角的分组选择标签。
  - 原因：用户期望分组切换通过右键完成，不希望卡片右上角常驻一个标签图标。
- 恢复模型卡片右键切换分组。
  - 当前行为：在 API 卡片主体右键，会弹出“切换分组”菜单；选择分组后调用现有 `onGroupChange` 更新 `group_name`。
  - 边界：没有修改数据库 schema，没有恢复旧版 `model_groups` 独立表。
- 取消 API 卡片固定最小高度。
  - 原因：原 `min-h-[138px]` 造成卡片底部空白过大，和旧版紧凑工具面板不一致。
- 模型能力信息支持自动换行。
  - 原因：`识图 / 音频 / 视频 / PDF / ...` 等能力信息之前被单行截断，截图中出现遮挡和看不全的问题。
  - 当前行为：能力、上下文、输出等信息用多行文本显示，避免遮挡。
- 合并搜索/分组/API 池三个圆角大容器。
  - 原因：独立卡片分散，视觉上不像一个连续的 API 管理工作区。
  - 当前行为：搜索工具条、分组标签和 API 卡片区合并为同一个 `Card`，内部用分隔线分层。
- 调整顶部三个主操作按钮。
  - 顺序改为：`添加模型`、`添加分组`、`一键测速`。
  - 三个按钮统一使用 outline 样式和一致最小宽度，不再让“添加模型”呈现黑色主按钮。
- 分组标签增加右键菜单。
  - `auto` 分组不提供删除或重命名。
  - 菜单只显示“重命名分组”和“删除分组”两个动作，不再重复显示分组名，并收窄到动作文本所需宽度。
  - 空的本地分组删除时只移除本地标签顺序。
  - 已有 API 的分组删除时，会把该组 API 条目迁移到 `auto`。
  - 删除分组前增加二次确认，避免误删。
  - 分组重命名时，会把该组 API 条目迁移到新分组名；空分组只更新顶部标签。
- 模型卡片测速结果移动到右下角。
  - 原因：测速后秒数放在标题/渠道行里不够直观。
  - 当前行为：整张卡片右下角显示测试中、失败或响应时间结果；响应秒数不再带括号。
- 收紧模型卡片底部空白。
  - 原因：测速结果原先依赖额外底部 padding 和绝对定位，造成卡片右下角像多出一行空白。
  - 当前行为：测速结果进入卡片内容底行右侧，卡片高度随内容自然收缩。
- 将 API 管理搜索区按钮从“刷新模型列表”改为“刷新列表”。
  - 原因：该按钮只刷新当前 API 条目查询，不会从渠道重新拉取上游模型目录，旧文案容易误解。
- 移除 API 管理搜索区“刷新列表”按钮。
  - 原因：该按钮只会重新读取当前 API 条目列表，不会获取渠道模型、不会测速，实际意义弱且容易误解；列表已有事件刷新机制。
- 固定 API 管理顶部三个操作按钮在右上角。
  - 原因：原标题区允许换行，说明文字较长时按钮组会被挤到下一行；现在左侧标题说明可收缩，右侧“添加模型 / 添加分组 / 一键测速”按钮组固定在标题行右侧，和渠道管理、令牌管理一致。
- 收窄 API 管理右上角三个操作按钮。
  - 原因：按钮保留 `min-w-32` 后宽度明显大于渠道管理和令牌管理的右上角按钮；现在去掉固定最小宽度，按文字和图标自然宽度显示。
- 微调 API 管理右上角按钮组垂直位置。
  - 原因：按钮组原先贴近标题区上沿，现在改为标题行垂直居中，更接近渠道管理页右上角按钮位置。
- 精简 API 管理标题说明文案。
  - 当前文案：`快捷键：Shift+Click: 全开/全关，Ctrl+Click: 置顶`。
  - 原因：保留实际操作提示，去掉重复的功能描述。

  - 原因：字体最高优先级已统一为 `抖音美好体`，局部英文数字也必须服从全局字体规则。

  - 原因：和 API 管理页主操作按钮保持一致，不再使用黑色主按钮。

  - 原因：渠道名称应完整显示；响应和模型数主要是短数字，不需要占用过多横向空间。

  - 边界：不新增数据库表，不改 schema，继续使用现有 `api_entries.group_name`。
- 渠道编辑弹窗表单上半区改为两列等宽布局。

  - 当前行为：提示显示在“编辑渠道/添加渠道”标题右侧，单行截断，不改变下方内容区高度。
- 入驻分组控件改为可输入的窄下拉。
  - 点击输入框会显示当前已有分组，列表宽度按输入框收敛，不再使用浏览器默认过宽的 datalist 弹层。
  - 用户也可以直接在输入框中键入新分组名，保存时按新分组迁移。
- 入驻分组输入框和下拉宽度改为占满右侧半列。
  - 原因：在两列布局中，`备注` 和 `入驻分组` 应该等宽；不再使用固定 `w-60`，避免显得过窄。
- 入驻分组下拉列表改为两列显示。
  - 原因：本地分组较多时，单列列表在弹窗内显示不完整；两列能在同一高度内展示更多分组名称。
- 模型列表工具栏合并到标题行。
  - 当前行为：模型列表标题、已选数量、搜索框、`全选列表`、`清空已选` 和 `获取模型` 位于同一工具行。
  - 原因：原搜索框和按钮单独占一行，压缩模型列表可视区域；短文案和同排布局能减少纵向占用。
- 获取模型列表后不再自动勾选模型。
  - 新增渠道：拉取到的模型默认全部不勾选，需要手动选择。
  - 编辑渠道：重新拉取模型时，只保留该渠道原先已选择的模型，不自动追加新模型。
- 渠道列表改为按渠道名称自然排序。
  - 当前顺序：数字开头排最前，英文字母按 A 到 Z，汉字按 `zh-CN` 拼音序。
  - 原因：渠道管理的主要识别信息是渠道名称，按响应速度或启用状态排序不够直观。
- 修复复制渠道后出现两条相同成功提示的问题。
  - 根因：应用同时在 `main.tsx` 和 `MainShell.tsx` 挂载了两个 `sonner` 的 `Toaster`，同一个 toast 被渲染两次。
  - 当前行为：只保留全局 `Toaster`，并统一为 `top-center`、`richColors`、`closeButton`。

  - 原因：该软件为个人本地使用场景，API Key 不需要默认隐藏；同时移除右侧“显示/隐藏”按钮，减少输入框噪声。

  - 原因：多模型渠道单列列表过长，两列布局能在同一高度内展示更多模型，便于勾选和核对。

  - 原因：模型行本身已有勾选状态，标题区已保留已选数量；底部重复展示已选模型会挤占模型列表可视空间。
